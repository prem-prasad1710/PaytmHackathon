## 1. Architecture summary

Three-layer payment fraud stack plus a separate message/QR/screenshot copilot:

```text
[Web Vite/React :5173] ──► [Node Express API :8787]
                              │
                              ├─ /api/analyze          → offline rule engine ± Grok ± text ML blend
                              ├─ /api/transaction-risk → Payment Guardian (text IsolationForest or heuristic)
                              ├─ /api/reports*         → community reports → threat map
                              └─ /api/fraud/*          → FraudEngine
                                    ├─ ML (Python FastAPI :8001, XGBoost txn model)
                                    ├─ Graph (graphEngine + in-memory ledger from fraudDemoWorld.json)
                                    └─ Rules (ruleEngine)
                                         └─ riskAggregator → SAFE / WARNING / BLOCK + explainer
[Expo mobile] ──► same analyze/history/confirm flows (subset; no QR/Lab/map)
[shared/] offlineEngine.js + fraudDemoWorld.json (imported by server + copied into web)
```

**Decision path (payments):** ML weight 0.40 / Graph 0.35 / Rules 0.25, with hard overrides (blocked recipient, confirmed network + extreme velocity) and floors when engines disagree or ML is down. GenAI is **not** in the decision path; `explainer.js` builds user-facing reasons from engine evidence.

**Graceful degradation:** If Python ML is down, `mlAvailable: false`, ML weight dropped, graph+rules still protect. If Grok key missing, analyze uses the offline scenario engine (and optional text ML blend when `:8001` is up).

## 8. Prioritized feature plan (Phase 2 candidates)

Keep only what fits existing code and is buildable in ~1–2 days. Each idea ties to a concrete touchpoint.

### P1 — High judge impact, fits existing lab story

1. **Scammer’s playbook timeline**  
   - **Idea:** Map the current payment/message into stages of a known script (bait → trust → urgency → collect/QR → mule cash-out) and show “you are here”.  
   - **Impact:** High — narrative judges remember; not a generic score.  
   - **Effort:** M (0.5–1 day)  
   - **Files:** `shared/offlineEngine.js` (scenario metadata), `server/fraud/explainer.js`, new `web/src/components/fraud/PlaybookTimeline.jsx`, wire into `FraudLab.jsx` + `Analyze.jsx`.  
   - **Risk:** Low if additive UI; avoid changing aggregator thresholds.

2. **Live judge demo mode (scripted E2E)**  
   - **Idea:** One “Demo” button: Normal → Suspicious → Scam → Stream threat → ML-offline still BLOCK → Copilot KYC SMS, with spoken captions / auto-advance.  
   - **Impact:** High — removes presenter fumble.  
   - **Effort:** S–M  
   - **Files:** `web/src/pages/FraudLab.jsx`, `web/src/services/fraudApi.js`, small `web/src/data/judgeScript.js`.  
   - **Risk:** Low (orchestration only).

3. **Explainable reasons in plain Hinglish (user + agent view)**  
   - **Idea:** Dual card: “Why we blocked” (customer Hinglish) vs “Why the bank can defend this” (rule ids + graph facts). Rephrase from `explanation[]`, never from free-form LLM as decision.  
   - **Impact:** High for Paytm trust/compliance judges.  
   - **Effort:** S  
   - **Files:** `server/fraud/explainer.js`, `DecisionCard.jsx`, optional LLM **rephrase-only** behind flag in `server/index.js`.  
   - **Risk:** Low if LLM stays out of score path.

### P2 — Differentiating, still day-scale

4. **Family / trusted-contact guardian approval**  
   - **Idea:** On WARNING/BLOCK (or first-time payee > ₹X), require a second device approval from a trusted contact (demo: localStorage + QR deep-link / mock push).  
   - **Impact:** High socially; very Paytm-family.  
   - **Effort:** M–L  
   - **Files:** `ConfirmPay.jsx`, `paymentFlow.js`, new `server/fraud/guardianApproval.js` (in-memory), optional mobile `ConfirmPayScreen.js`.  
   - **Risk:** Medium (new flow paths); keep mock-pay only.

5. **Cooling-off / time-lock for high-risk first-time payees**  
   - **Idea:** Extend existing ConfirmPay cooldown: first-time payee + elevated risk → 30–120s lock + “schedule pay” instead of instant.  
   - **Impact:** Medium–High; product-shaped.  
   - **Effort:** S  
   - **Files:** `ConfirmPay.jsx` (`COOLDOWN`), `guardianApi.js` / `ruleEngine.js` (`LARGE_FIRST_PAYMENT` already exists).  
   - **Risk:** Low.

6. **Pre-payment intent / coercion detection**  
   - **Idea:** Lightweight signals: urgency/fear lexicon, “on a call with support”, screen-share app names in pasted text, collect-request + coaching phrases → elevate to Guardian overlay even if amount looks normal.  
   - **Impact:** High (real scam MO); unique vs classifier demos.  
   - **Effort:** M  
   - **Files:** `shared/offlineEngine.js` (new rules), `Analyze.jsx`, `GuardianOverlay.jsx`; optional `ml/text_model/features.py` keywords.  
   - **Risk:** Medium (false positives) — ship as WARNING with explainable flags, not silent BLOCK.

7. **Money-mule network visualisation upgrade**  
   - **Idea:** Animate fund-forward edges from ledger (`RAPID_FUND_MOVEMENT`), highlight mule hop depth, click-to-block demo.  
   - **Impact:** Medium–High visual wow in Lab.  
   - **Effort:** M  
   - **Files:** `NetworkGraph.jsx`, `graphEngine.js` / `ledger.js` network payload.  
   - **Risk:** Low if read-only viz.

### P3 — Nice stretch / language & offline

8. **Hindi/Hinglish + regional message understanding**  
   - **Idea:** Expand Devanagari + Hinglish templates; add 1–2 more scripts (e.g. transliterated Tamil/Telugu keywords) in offline engine; show `detected_language` in UI.  
   - **Impact:** Medium–High for India relevance.  
   - **Effort:** M  
   - **Files:** `shared/offlineEngine.js`, `ml/text_model/dataset.py` / `features.py`, `HighlightedMessage.jsx`.  
   - **Risk:** Low if additive scenarios + tests.

9. **Real offline-first behaviour badge**  
   - **Idea:** Explicit UI mode: kill API/ML in demo and still show Lab graph+rules BLOCK + analyze offline; “Works on bad networks / no Grok key” panel. Align `VITE_USE_MOCK` with transparent banner (today forced mock can hide that the API works).  
   - **Impact:** Medium (ops honesty).  
   - **Effort:** S  
   - **Files:** `analyzeApi.js`, `Navbar.jsx` / `FraudLab.jsx` status chips, `server/fraud/mlService.js` already degrades.  
   - **Risk:** Low.

10. **Counter-scam honeypot reply suggester**  
    - **Idea:** For High Risk messages, suggest safe replies that waste scammer time *without* sending money or OTP (“Bhai official branch aa jao”, “Call 1930 pe verify kar liya”). Copy-only, never auto-send.  
    - **Impact:** Medium (memorable, slightly spicy).  
    - **Effort:** S  
    - **Files:** `Analyze.jsx` / `ActionButtons.jsx`, templates in `offlineEngine.js`.  
    - **Risk:** Low if clearly labelled advisory; avoid anything that looks like entrapment of real users.
